# MOC 实现与工程改进日志

## 交付范围

本次完成已批准的 moc-core 实现计划，并对协议、上游兼容、内核和 CLI 做了一轮有证据的行为修复。所有实现与修改均在当前工作区完成，没有向远程仓库推送，也没有导入参考项目的实现源码。

- **moc-protocol**：协议版本升至 1.1；增加会话模式、计划批准、手动压缩、交互提问和任务列表 DTO；补齐 AgentService、服务端分发、客户端能力协商及对应更新事件。旧客户端缺省能力仍可反序列化。
- **moc-llm**：增加 Responses 原生 input 回放、服务端压缩阈值、流式与非流式 compaction item，以及 `/responses/compact` 请求、响应和重试处理。同步所有响应构造与流累加调用点。
- **moc-core**：实现 TOML 分层配置、模型角色与兼容配置、JSONL 会话及文件锁、稳定系统提示词、上下文文件加载、工具注册与授权、流式轮次、模式和计划流、工作区检测及 remote/shake/soft 压缩。
- **工具**：提供 bash、job、read、edit、write、grep、find、todo、ask、submit_plan；工具结果维持原调用顺序，读类工具有界并发，写入与交互工具串行。
- **moc-cli**：实现内嵌 core 的 `moc` 命令、交互 REPL、单轮 `--print`、会话恢复、模型与模式切换、计划批准、压缩、撤销、任务渲染和 SIGINT 取消。

## 参考项目与取舍

### Oh My Pi

依据本地 `omp://natives-text-search-pipeline.md` 与 `omp://compaction.md` 中已读取的搜索和上下文设计：

- 保留确定性的路径顺序与分页；将 grep 的命中计数和上下文行计数分开。使用路径有序的小批并行搜索，不让线程完成先后决定结果顺序。
- 工具输出归档与模型侧截断分离；取消采用令牌与进程组所有权，不靠脱离所有者的后台任务继续占用资源。
- 系统消息、工具定义与历史前缀保持稳定；动态时间、任务完成和工作区通知只进入消息尾部。
- 压缩保留 tool_call/tool_result 配对，原生载荷与真实尾部去重，失效载荷不能成为删除上下文的依据。

### Grok Build

依据官方 README：<https://github.com/xai-org/grok-build>。

- 保持前端渲染、运行时、工具和工作区职责边界，CLI 不直接重做模型轮次循环。
- 将既有 `service/turn.rs` 拆为请求构造、流事件、工具执行、工作区通知模块，复用单份 ToolCtx，不建立重复的一套状态或工具 API。
- `--print` 维持只输出最终正文的脚本契约；交互模式保留增量和事件。取消不破坏 REPL 的后续输入。
- 摘要沿用批准计划中的结构化 checkpoint，保留用户纠正、路径、命令、错误、当前工作和下一步。

### DeepSeek Harness 与 hashline 参考

官方入口：<https://github.com/deepseek-ai/deepseek-harness>。第三方锚点编辑参考：<https://github.com/Rianico/dsh-better-edit>；后者不是 DeepSeek 官方组件。

- 借鉴清晰的能力边界，但继续使用现有 Rust trait、注册表和 crate 分层，没有为当前需求增加动态插件运行时。

- 完整重读释放退役锚点；部分重读不擅自扩大授权范围。
- 撤销校验编辑后的磁盘版本，拒绝覆盖外部修改；只有恢复成功才消费记录，并让连续撤销认可刚恢复的 inode。
- 不采用参考项目 README 的性能百分比作为本项目结论；本次没有宣称未经测量的吞吐或 token 节省比例。

## 具体修复

### 生命周期与取消

- 将在飞轮次的收尾交给 core 所有的任务集合；前端断开后仍保存部分 assistant 内容，补齐未执行工具的取消结果，再释放会话锁。
- 上游请求、流读取及压缩请求均响应取消。后台任务不附着到发起轮次的取消令牌；会话卸载或 core 退出时统一终止并回收。
- 管道和 PTY 使用同一完成句柄，支持前台、后台、自动后台化、超时及 job kill/wait。后台化不会重置命令的超时起点。
- 进程组负责回收子孙进程，stdin 与输出读取并行，避免大输入导致管道互相等待。
- 已结束的后台 worker 句柄及时回收；job 关闭时禁止创建不可管理的后台任务。

### 会话与恢复

- 列表从 JSONL 投影最新标题、模式和模型，不再用旧缓存覆盖其他进程的新状态。
- 获取会话文件锁后检测磁盘修订；发生外部追加或原子替换时重新加载并重开文件句柄，避免向旧 inode 继续追加。
- 后台日志编号恢复时扫描已有日志，并以 `create_new` 预留路径，防止 resume 覆盖原日志。
- 会话修改和撤销受轮次互斥及文件锁保护；模型解析错误明确映射为 InvalidParams。

### 文件与检索

- grep 使用有界候选扫描、二进制检测和流式单文件搜索；计数只统计匹配行，合并上下文，支持相对搜索根的 glob 与确定性分页。
- find 用容量受结果上限约束的堆维护结果；路径排序不读取不必要的完整元数据。扫描上限包含未命中的访问项。
- 文件工具规范化已有路径，沿符号链接编辑真实目标，不把链接本身替换掉。
- 超过单次输出预算的长行显示未授权占位，后续短行仍可展示并获得锚点，避免反复卡在同一 offset。
- read 目录展示按 mtime 排序，限制深度和每层数量，不递归跟随符号链接。
- 截断标记只写入归档路径，不替换正文中恰好出现的相同字符串。
- 跨文件 move 保留原坐标语义与提交回滚，成功后再登记撤销；空操作循环被显式拒绝。

### 工作区与上下文

- 修正 Git 子目录中的路径基准。扫描达到上限时返回部分覆盖及通知，而不是终止模型轮次。未覆盖路径不被误判为新增或删除。
- ask/plan 检测违规但不回滚工作区，避免覆盖用户同时进行的编辑。
- remote 载荷解码失败或换模型时恢复可用日志历史，不用占位摘要冒充被丢失的正文；reset 边界仍生效。
- 原生压缩保存成功文件操作清单，并去除与保留尾部重复的响应 item。只返回原始尾部、没有 checkpoint 的压缩结果不会被接受。
- `auto_continue=false` 在压缩维护完成后结束当前轮次，避免继续发起模型请求；工具调用配对不因停止维护而破坏。
- 固定输入测试覆盖取消时的部分正文、工具顺序、溢出恢复、原生回放、只读违规、计划批准与 CLI SIGINT。
