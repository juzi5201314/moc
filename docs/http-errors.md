# 上游错误与自动重试

终端 TUI、浏览器 Web 与命令行共用同一套上游错误解析与重试策略，出错时统一给出可读的中文说明与排查方向。

## 错误信息包含什么

报错按固定顺序呈现：HTTP 状态码与中文含义、错误分类、上游原始消息、请求 ID / 错误码、Cloudflare Ray ID、`Retry-After`（若上游提供）、请求体与图片诊断，以及针对性建议。例如：

```text
HTTP 431 请求头过大 [Unknown]
上游消息：request header fields too large (request_id=req_example)
排查建议：检查附加请求头、Cookie 和重复鉴权字段；压缩图片请求体不能解决请求头超限。
```

- 界面中的上游消息截断至 512 字符并折叠 HTML 错误页，避免整页源码刷屏；原始报文仍保留在日志与底层结构中以便排查。
- 标注 `[Unknown]` 仅代表尚未归入特定细分类型，不代表无法恢复；在未收到明确永久拒绝前，仍会按重试策略继续尝试。

## 状态码与语义覆盖

- **标准状态码**：完整覆盖常见 4xx / 5xx，以及意外的重定向或成功状态异常。
- **主流网关惯例**：识别 Cloudflare `520`–`526` / `530`、Anthropic `529`（服务过载），以及 Nginx 等常见非标准码（`444`、`494`–`497`、`499` 等）；对不常见非标准码标注“定义因服务而异”，不胡乱猜测。
- **语义优先于笼统状态码**：例如上游返回 `429` 且明确指出 `insufficient_quota` 时，直接提示检查账户额度而非盲目等待；`400` 附带上下文超限时，与请求体字节超限区分开来。
- **HTTP 524**：无论是否含图片，统一按超时策略处理；随错附带的请求体积和图片统计仅用于辅助排查，不会触发静默删图。

## 自动重试规则

重试原则是**“除非上游明确表示原样重试无效，否则在预算内退避重试”**：

- **会自动重试**：限流（`429`、`rate_limit_*`）、服务过载（`529`）、临时 5xx、请求超时（`408`/`524`）、网络断开、未明确永久失败的冲突（`409`）及未分类临时错误。
- **不会原样重试**：账户欠费或额度耗尽、鉴权/权限错误（`401`/`403`）、资源不存在（`404`）、参数或格式错误（`400`/`422`）、请求体或请求头过大（`413`/`431`）、内容审核拒绝、本地构造失败，以及用户主动取消。
- **专用恢复通道**：上下文超窗与思考签名不匹配不走普通重试，而是进入各自的专用恢复流程。
- **共享重试预算**：一次逻辑回答中，HTTP 200 内的错误体、首字前错误、连接中断和生成中途断流共用同一 `providers.<id>.retry.max_attempts`（默认最多尝试 10 次，退避从 0.5 秒指数增长至最高 300 秒，带随机抖动；尊重上游整数秒 `Retry-After`）。完成一轮完整回答后重新计数，用户取消会立刻打断等待。

## 生成中途出错如何处理

如果流式输出写到一半中断并触发重试：

- **自动清理半截内容**：丢弃本次未完成的回复、思考和尚未执行的工具调用，不写入模型历史；已完成的先前轮次与工具结果完整保留，绝不会重复执行已经跑过的工具。
- **前端体验**：TUI 与 Web 会清空那段失败预览并显示重试倒计时；行式 CLI 与 ACP 无法擦除已打印的文字，会明确输出一条提示说明上一段预览作废，随后展示重试结果。
- **旁路问答**：`/btw` 沿用同样的重试预算与预览清理逻辑，不影响主对话。
