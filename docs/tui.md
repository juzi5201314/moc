# TUI 使用说明

## 布局

自上而下：

- 顶部信息条（品牌 · git 分支 · 工作目录 ｜ 上下文进度条 · 费用）
- 转写区（markdown 渲染、工具调用盒、diff、todo 树）
- 圆角输入框（斜杠补全、历史、粘贴 chip、图片 chip；多行输入自动长高，下边框左端是帮助键提示、右端是模型 · 模式）
- statusline

内容左右各留 2 格边距、块之间以留白分隔：

- 用户消息是保留圆角边框且背景与转写区一致的面板（末行右侧给本地时间）
- 助手回复带「耗时 + 时间」尾注
- 思维链展开成引文带（左竖线 + 抬升底色）

美术基调：GrokNight 深色主题（`#141414` 底、TokyoNight 强调色），diff 红绿底、OneHalfDark 代码高亮，启动时按终端能力从 truecolor 量化到 256/16 色。

支持鼠标：滚轮滚动、点击标题在「完整 ↔ 该块当前收起形态」之间切换（思考、工具、IRC 卡片，见「显示档位」）、拖选文本后 `y` 复制；点击输入框下边框右端的模式名会就地弹出模式菜单（图例本身样式不变），点条目即切换会话模式，`↑↓` + `Enter`、`Esc` 同样可用。

助手正文里的**顶层表格**下方会挂一个右对齐入口 `▸ 可视化图表`：点击后该表格就地换成像素图（条形、分组条、成对条、折线、堆叠、进度、热力图或散点，按表格语义自动选型），再点 `▾ 还原表格` 换回。入口只在终端支持图形协议（kitty / sixel / iTerm2）且能取到单元格像素尺寸时出现——图片按整数格 1:1 贴出，终端不缩放，文字才不会发虚；拿不到格尺寸就不出图。图表文字用随 crate 内嵌的 Noto Sans Mono CJK SC 子集光栅化，缺字才回退系统字体。切换是进程内视图态，不写入会话文件；正文继续流式增长时该块的图表会自动退回表格。`MOC_CHART_GRAPHICS=kitty|sixel|iterm2|none` 可强制协议，`MOC_CHART_CELL=8x18` 可指定单元格像素尺寸（必须与终端真实值一致）。

## 配置与运行中输入

`/config` 或 `Ctrl+G` 打开设置页，包含模型、供应商、指令、技能、工具、上下文、会话、MCP、OpenViking、界面和高级设置。供应商与模型按分组展示，`←→` 或 `Enter` 展开／收起；`↑↓` 选择，`Enter` 就地编辑单行字段，多行内容在弹出的小窗里编辑并用 `Ctrl+Enter` 应用。模型角色（主模型、探索子代理模型、计划模型）与 `Ctrl+P` 共用同一个可搜索模型选择器，`Enter` 或 `Space` 打开，选中模型的同时确定思考等级（`Tab` 或 `←→` 就地切档，焦点不离开候选列表）；候选行右侧的规格卡只列真实生效的项——上下文窗口、输出上限、输入模态、价格、服务端压缩与思考等级，没有值的项连字段名都不出现；正文窄于 74 列或行数容不下整张卡时收起，改在行尾显示上下文数字。explore 的「沿用主模型」和 plan 的「沿用当前会话模型」是候选列表最前面的伪条目。`Space` 切换开关，`Delete` 删除整组，`R` 恢复默认值，`F2` 切换全局／项目，`F4` 显示高级项，`/` 搜索。**每次修改都会立刻写入配置文件并让内核生效，不需要手动保存**；`Ctrl+Z` 撤回，`Ctrl+Y`（或 `Ctrl+Shift+Z`）重做，撤回记录只存在于当前进程内。密钥默认隐藏，`F6` 临时显示；写入前会校验配置及外部修改冲突。

运行中 `Enter` 会把消息作为补充要求交给正在执行的模型；底部 statusline 显示 `Working`、`Thinking`、`Responding`、`Running`、`Waiting` 或 `Stopping`，输入框边框显示 `Esc Stop`。可在"界面"页改为"先停下再重新提示"，即停止当前回答后发送新消息。`Ctrl+Enter` 把消息排到待发送队列（显示在输入框右上方），点击可重新编辑，点击 `×` 取消。队列按会话隔离，在当前回答结束后依次发送；设置页或弹窗打开时暂停派发，关闭后自动继续。模型切换（含确认后的上下文压缩）与 `/compact` 在飞时同样暂停派发，等它们收尾再发送，不会把消息撞成 `SessionBusy` 报错。

输入框为空且当前没有运行中的提示时连续按两次 `Esc`，会打开消息回退选择器。`↑↓` 在当前用户消息的请求、模型回复和工具结果之间移动，`←→` 切换用户消息，`Enter` 会创建一个保留原会话的回退分叉并将上下文切换到选中位置；选中用户消息时会把原消息恢复到输入框，供修改后重新发送。分叉是完全独立的会话：模型侧看不出它与普通会话的区别（没有子代理契约、没有 `yield`、不进子代理名册），出身只对用户可见——回退完成时的提示会点名来源，`/resume` 列表里分叉会话在标题后标注 `← 来源`（来源已不在列表时退回会话短 id）。

"界面"页可配置快捷键、思考与工具的默认显示档位、完成／需要你回答时的通知。通知只在终端失焦时发送，通过 OSC 9 交给终端呈现；操作系统通知支持取决于终端。鼠标交互自动启用，没有捕获开关。

上游回显的模型 id 或推理强度与本地请求不一致时（网关降级、别名映射、静默降低强度等），转写区右上角会弹出一条告警胶囊，形如 `model a → b ｜ effort max → high`：复用右下角一次性提示的样式，但改用橙色强调，8 秒后自动消失，同一次提示内再次不一致只替换不堆叠，新提示开始时清除。只有上游确实回显了对应字段才会告警，网关不作声不产生任何提示。

`Ctrl+Enter`、`Ctrl+M` 这类组合键需要终端支持区分；不支持时 `Ctrl+M` 等同于 `Enter`，切换会话模式请用 `Alt+M`（键位可在设置页重绑）。

模式菜单与 `/mode` 支持标准、计划、PTC 和 `(clm)` 实验模式。进入计划模式会应用 `[models.roles].plan` 指定的模型（设为 `none` 则沿用当前模型）；手动切出时恢复进入前的模型，批准执行则使用审阅窗口选中的执行模型。`/clm-experimental` 可直接启用 CLM；也可用 `--mode clm-experimental` 创建新会话。CLM 模式会在 TUI 图例显示 `(clm)`，并在首次请求后锁定本会话模式，不能再切换回其它模式；原始会话日志仍完整保留，模型维护的是独立实时上下文视图。

计划流程先由模型调用 `write_plan` 保存到 `local://{plan_id}.md`，再调用 `exit_plan` 结束本轮并打开审阅。审阅支持当前会话执行、压缩当前会话后执行、在新会话执行和继续计划；执行模型默认取打开审阅时的完整会话模型 selector，点击模型 ID 或按 `Ctrl+P` 可复用搜索框选择任意已配置模型并挑思考等级，不提前切换会话模型。压缩与执行均使用最终选定的模型。选择"继续计划"或按 `Esc` 只关闭窗口，保持待审计划和计划模式，不自动对话；随后可用 `/confirm-plan` 重新加载同一份待审计划。新会话执行会先切换到已载入的子会话，再发送执行提示。

## 显示档位

思考块与工具块各自有三档显示，`Ctrl+T` 管思考、`Ctrl+O` 管工具，循环切换（隐藏 → 简略 → 完整），右下角会提示当前档位；默认都是**简略**，"界面"页可改启动档位，`--detail hidden|brief|full` 可临时覆盖两层（不影响行式／`--print` 输出）。

| 档位 | 思考块 | 工具块 |
| --- | --- | --- |
| 隐藏 | 只留 `◆ 思考耗时 X.Xs` 一行 | 只留标题行（工具名 + 参数摘要） |
| 简略 | 正文末尾 4 行 | 正文最多 6 行（diff 同样 6 行），超出补一行 `⋯ 还有 N 行` |
| 完整 | 正文全文 | 正文全文，不截断 |

补充规则：

- 工具正文只对「有输出的工具」显示：`bash` 这类只展示结果尾部的最新若干行；`read`／`find`／`todo` 这类只回显参数的工具在任何档位都只占一行（`read` 的摘要带行号范围，如 `read crates/moc-tui/src/app.rs:585-670`），失败时正文是错误原因，仍可展开查看。
- 同一批次（同一模型响应中的同名工具）合并成树形块：档位取组首块，简略／完整档在每个成员的摘要行下追加该成员的正文。
- 懒渲染保证只有视口内的块真正构造行：完整档不会因为历史很长而变慢。
- 点击块标题在该块的「完整 ↔ 当前收起形态」之间切换：简略档下收起就是预览，隐藏／完整档下收起只剩标题行。

斜杠命令包括 `/help` `/new` `/model` `/resume` `/mode` `/confirm-plan` `/clm-experimental` `/ask` `/agents` `/compact` `/usage` `/config` `/settings` `/memories` `/context` `/quit`；`/confirm-plan` 仅在计划模式且有已写入的待审计划时打开审阅，其余情况只显示提示。`/usage` 展示当前会话各模型的调用次数、输入／输出 token、缓存命中率、思考 token、TPS 与激活时间，并附全部模型总和。`/context` 打开上下文正文窗（见下文），顶部信息条右端的进度条点击打开的是上下文占用窗，两者看的是同一份上下文。输入框以 `!` 开头的内容直接执行 Bash 并把命令及结果写入 agent 上下文，以 `!!` 开头则执行后只在界面显示，不写入 agent 上下文。`/model` 与模型选择器把目标模型和思考等级一起选中：切到别的模型时用该模型支持的最高等级，停在同一个模型时沿用配置或会话里写的等级；目标模型装不下当前上下文时先询问，确认后先切换再由新模型压缩上下文。

### 子代理

人类面只有一个子代理命令 `/agents`（等同 `Ctrl+N`）：打开名册后 `Enter` 把主 TUI **整个聚焦到该子代理的会话**——转写、输入框、状态栏、`Ctrl+C` 取消都属于它，直接打字发送即可交流（运行中在下一次安全边界注入，空闲则唤醒新回合）；`Esc`（输入框为空）或双击 `←` 返回主会话，返回时主会话按磁盘真相重载并还原回来前的草稿。聚焦期间头部常驻 `▸ 子代理 <标题>` 提示，名册与侧栏仍挂靠在主会话上，`Ctrl+S` 停止选中的子代理（聚焦时停的就是眼前那个）。创建子代理由主模型决定（`spawn_agent`），界面不提供人机新建入口。

## 剪贴板

`Ctrl+V` 粘贴剪贴板里的图片，没有图片时粘贴文本；Linux 下图片需要 `wl-paste`（Wayland）或 `xclip`（X11），WSL 直接读 Windows 剪贴板，Windows Terminal 里按 `Ctrl+V` 即可，无需额外配置。`y` 复制拖选内容到终端与系统剪贴板（OSC52）。

## Statusline

内置渲染是「左侧 todo 进度 + 右侧统计」两段：`☑ 2/9 … ⇅ 输入 › 输出 › tok/s › 提示计时 › 费用`；模型与模式在输入框下边框右端，工作目录/分支/上下文进度在顶部信息条（费用需要模型 pricing 配置）。

可在 `~/.moc/tui.toml` 用模板自定义（占位符按语义着色）：

```toml
statusline = "{model} * {mode} -> {workdir}"
```

可用占位符：`{model}` `{mode}` `{context}` `{context_percent}` `{workdir}` `{branch}` `{todo}` `{tokens_in}` `{tokens_out}` `{tok_s}` `{prompt_elapsed}` `{cost}`。

## 上下文占用窗

点击顶部信息条右端的上下文进度条打开。窗内按 `system`、`project`、`skills`、`tools`、`messages` 逐块列出估算 token 与占已用上下文的比例，每块的色标与下方色条上对应那段同色。色条按模型上下文窗口定标：已用部分落在左侧，右侧 `─` 是剩余窗口，空会话整条都是空窗口；色条下方标注各分块右界的累积用量，空间不够时只保留挤得下的标注，「已用总量」与右端窗口上限优先。token 一律按 k 显示（`9030 → 9.03k`，非零但不足 10 token 记 `<0.01k`），全 TUI 同一套写法。

## 上下文正文窗

`/context` 打开：窗内列出**真正送进模型的内容**，顺序与请求一致——系统提示片段（`intro`、`tool policy`、`ptc runtime`、`mcp servers`、`repo rules`、`skills`、`subagent`、`environment`、`append`）、逐个工具 schema（分块名就是工具名）、注入消息（`compaction summary`、`active plan`、`active todos`、`grok build summary`、`system reminder`）与会话消息（`user`、`assistant`、`tool result`、`bash`、`agent`）。每块一行标题，`▌` 色标与分块名同色（按分块顺序取调色板），右端是该块单独估算的 token；标题栏显示合计与窗口上限，与占用窗、顶部进度条同口径。新会话只有前面组装好的上下文，消息部分为空。

正文超过 6 行的块默认折叠成前 6 行加一行「… 还有 N 行 · 点击展开」，点标题或正文任意一行展开，再点收起。单块正文超过 256 KiB 时由 core 按字符边界截断，块尾标注被丢掉的字节数。窗口约占终端四分之三宽、五分之四高（上限 120×40），右缘是可拖拽的滚动条（按在滑块上保持抓取点，按在轨道空白处把滑块挪过来），鼠标滚轮一次三行。

键盘：`↑↓`/`k`/`j` 逐行滚动，`PgUp`/`PgDn` 翻页，`Home`/`End`（`g`/`G`）跳到顶／底，`Tab`/`Shift+Tab` 切换分块（自动滚进视口，高亮该块标题），`Enter`/`空格` 展开收起当前分块，`e`/`c` 全部展开／收起，`Esc`（或 `q`）关闭。

窗里是会话状态里存着的内容；尾部提醒（当前模式、本地时间、后台任务、工作区变更、违规告警）每次请求现生成、不落进会话，因此不在窗内展示。

## 工具调用 Diff

edit / write 执行时由 core 生成结构化 diff（LCS 对齐、上下文 3 行、超限截断标记），经 `ToolFinished` 携带到前端；越出工作区的写入在授权弹窗里再给一次预览：`edit` 是待应用 diff（无法完整预览时不带），`write` 另附最多 40 行 / 4 KiB 的内容摘录，超出以 `[...]` 截断，确认后才落盘。

`edit` 接受单文件 `{path, edits}` 载荷，`edits` 只作用于一个源文件；`move` 可把源文件的行块搬到 `target_path`，因此一次调用可能同时写入两个文件（两侧都仍需先 `read`）。锚点在 read/diff 展示时分配，行位移后保持不变；同一行被重新展示时以最新锚点为准。批量多文件 `files` 载荷会以 `E_BAD_PAYLOAD` 拒绝。
