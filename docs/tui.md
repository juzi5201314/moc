# TUI 使用说明

## 布局

自上而下：

- 顶部信息条（品牌 · git 分支 · 工作目录 ｜ 上下文进度条 · 费用）
- 转写区（markdown 渲染、工具调用盒、diff、todo 树；右上角浮动 todo HUD）
- todo HUD（折叠为一行胶囊；悬停展开卡片，点击固定，卡片可拖动）
- 圆角输入框（斜杠补全、历史、粘贴 chip、图片 chip；多行输入自动长高，下边框左端是帮助键提示、右端是模型 · 模式）
- statusline

内容左右各留 3 格边距，所有块共用一套左缘网格，块与块之间恰好隔一行留白（每块自带一行尾随留白，转写首行不留白）：

- 块标记（用户 `>`、`◆`/`▸`/`✘` 工具与思考 bullet、批次 `•`、提示 `»`/`✘`）落在同一列；正文（助手回复、用户消息续行、工具输出、思考引文、IRC 正文、耗时尾注）统一落在其后两格的正文列
- 用户消息不加面板边框，末行右侧给本地时间
- 助手回复带「`⏱ 耗时` + 时间」尾注
- 思维链展开成引文带（左竖线 `▏`，正文与助手正文同列）
- 任何一行都不超出块宽：放不下的标题、摘要、单行正文以 `…` 收尾，不交给终端静默裁掉
- 状态词与块标题统一英文（`Thought`、`Tasks`、`running`、`done`、`failed` …），说明性提示与错误原文保持中文；键位统一写作 `Ctrl+P`、`Esc`、`PgUp`

美术基调：GrokNight 深色主题（`#141414` 底、TokyoNight 强调色），diff 红绿底、OneHalfDark 代码高亮，启动时按终端能力从 truecolor 量化到 256/16 色。

支持鼠标：滚轮滚动、拖动右缘滚动条（按在滑块上保持抓取点，按在轨道空白处把滑块挪过来）、点击标题在「完整 ↔ 该块当前收起形态」之间切换（思考、工具、IRC 卡片，见「显示档位」）、按字符拖选文本后用 `Ctrl+C`、右键或 `y` 复制（要使用终端自身的选区与复制行为，按住 `Shift` 拖选即可绕过应用的鼠标捕获，Windows Terminal 等终端都支持）；点击输入框下边框右端的模式名会就地弹出模式菜单（图例本身样式不变），点条目即切换会话模式，`↑↓` + `Enter`、`Esc` 同样可用。

凡是提示条、底栏或卡片底部写着的单键提示（如 `Esc 关闭`、`Enter 确认`、`Tab 切换范围`、`Shift+X 跳过`），点击就等同于按下该键；`↑↓`、`1-9`、`e/c` 这类多键或区间提示仍只作说明。弹窗打开时只有弹窗自己的键位可点，底下界面不会被点穿。点击输入框下边框左端的图例：空闲时打开帮助，运行中则停止当前任务；聚焦子代理时点击顶栏的 `Esc 返回` 回到主会话。模型、会话、子代理、Fusion、切换模型弹窗里滚轮移动选中项；模型、会话、子代理列表点击行即选中，再点一次已选中的行即确认；权限、Fusion、切换模型的选项行单击即执行；模型选择器的思考等级芯片可直接点选。帮助、上下文、上下文正文、模型、会话、子代理、Fusion 与回退视图这类只浏览不作答的弹窗，点卡片外即关闭；权限、提问与计划审阅不会因误点外部而关闭。回退视图里再点已选中的节点即回退到此处，计划审阅的动作行可直接点击执行。

助手正文里的**顶层表格**下方会挂一个左对齐入口 `▸ 可视化图表`：点击后在表格下方追加像素图（条形、分组条、成对条、折线、堆叠、进度、热力图或散点，按表格语义自动选型），表格始终保留；再点 `▾ 隐藏图表` 收起。图片宽度以 **720px 为上限**并左对齐，不随正文拉满，正好对应 omp autoGraph 的栅格密度；正文更宽时图片也不会被横向拉伸。入口只在终端支持图形协议（kitty / sixel / iTerm2）且能取到单元格像素尺寸时出现——图片按整数格 1:1 贴出，终端不缩放，文字才不会发虚；拿不到格尺寸就不出图。图表文字用随 crate 内嵌的 Noto Sans Mono CJK SC 子集光栅化，缺字才回退系统字体。热力图的色标在顶部图例区（底部不再有色标数据行）；全正且极差 ≥100 倍的条形图自动改用对数刻度，避免小值被压成 1px。切换是进程内视图态，不写入会话文件；正文继续流式增长时该块已展开的图表会自动作废并收起。sixel / iTerm2 无法单独擦除像素，隐藏图表后会清屏重绘一帧，kitty 则按图像 ID 删除。`MOC_CHART_GRAPHICS=kitty|sixel|iterm2|none` 可强制协议，`MOC_CHART_CELL=8x18` 可指定单元格像素尺寸（必须与终端真实值一致）。

表格按内容定列宽，单元格按显示宽度折行，表头与行之间用细线分隔；超宽时先按可读下限收缩再折行，连两格一列都放不下时改为逐字段列表。任何宽度下都不截断单元格内容。

除表格图表外，还有三类**内联图片**走上同一条贴图管线：工具结果（含 MCP 返回）里的 base64 图片、助手正文里的 `![](本地路径)`、以及 ```` ```svg ```` 代码块。它们按整数格 1:1 贴出，宽度上限 720px、高度上限 24 行，不放大；源图小于占位框时居中，留白填主题底色（sixel 因此直接跳过留白像素）。工具图片贴在正文列（与工具输出同一左缘），最多贴 4 张，超出补一行 `⋯ 还有 N 张图片`；markdown 图片与 SVG 贴在与正文左缘对齐的位置。同一张图在一处出现多次时各自独立放置，kitty 的像素数据仍只传一次；sixel / iTerm2 没有增量放置，位置或内容一变就整串重发。图片离开视口或换成纯文本后，kitty 按图像 ID 删除，几种索引色协议只能清屏重绘一帧。解码、缩放与协议编码都在后台线程完成：解码期间占位行显示 `图片解码中…`，解码完成但编码未完成时先留一帧空白，编码结果回来后由 `ImageEncoded` 事件触发重绘；终端不支持图形协议时既不下载也不解码，直接退回文本——工具图显示 `[图片 image/png]`，markdown 显示 alt 文本，SVG 仍按代码块高亮。

markdown 只解析本地文件与 `file://`（支持 `~/` 与 `%20` 这类百分号编码，相对路径按会话工作目录解析），`http(s)://` 与 `data:` 既不联网也不渲染，直接回落 alt 文本；路径不限制在会话目录内——模型本来就有 shell 权限，在这里加围栏挡不住读文件，只会让 `/tmp` 与 `$HOME` 下的合法图片打不开。引用块、列表与表格单元格里的图片保持文本形态（那里没有独立的贴图区域）。SVG 只允许 data URL 内嵌资源，`<image href="file:///…">` 一律丢弃，模型输出不该有能力把本机文件送进渲染管线。交给 resvg 之前，`currentColor` 和 `var(--fg)`、`var(--muted)`、`var(--border)`、`var(--surface)`、`var(--accent)`、`var(--success)`、`var(--warning)`、`var(--error)` 会换成当前主题的真彩色；模型自己写的 `#hex` 保持原样。

助手正文里的 mermaid 围栏（info 为 `mermaid`）画成字符图，只覆盖 `flowchart` / `graph`、`sequenceDiagram`、`stateDiagram`（含 `v2`）。颜色只用已有的边框、正文和灰色。流式输出里还没闭合的围栏保持代码高亮，闭合后才换成图；消息已经结束时，缺了闭合围栏也会尝试画。引用块和列表里的 mermaid 保持代码块。类图、ER、甘特等未支持的图种同样保持代码高亮。

工具结果里的图片**会随会话落盘**（base64 原样写进 transcript，这样恢复会话后模型仍能「看到」历史截图），但 TUI 的展示页会剥掉它们，所以恢复历史后不会重新显示。图片载荷只对会显示的前 4 张保留在内存里，其余只留内容摘要，避免几十 MB 常驻。

## 大正文与历史内存

旧历史正文可以冻结到私有只读快照，不要求先执行模型摘要；近期窗口同时受条数和字节预算约束，回退与导出仍读取完整原文。
超过 256 KiB 的助手 Markdown 使用分页压缩排版：每页 128 行，绘制只解码视口及上下各 128 行预读；屏外压缩布局超过 8 MiB 时淘汰旧块，重访再生成。
行样式、引用链接、表格和图片位置保留。首次解析与窗口宽度改变仍需重新处理正文，不是只解析屏幕上可见的一段原文。

## 空闲内存

Linux 下，首次绘制完成并静置约 2 秒后，TUI 可回收主程序中可从文件恢复的只读页。
后续交互结束后静置至少 30 秒，且距离上次回收至少 60 秒，才再次执行；持续提示、压缩或动画绘制期间暂停。
只回收启动时不可写的文件加载段，不碰堆、栈、会话正文或重定位页；检测到调试器附加时跳过。
重新访问设置等功能会触发缺页并使 RSS 回升。RSS 下降不等于系统文件缓存立即释放相同大小的物理内存。
其他平台继续使用操作系统默认的文件页管理。

## 配置与运行中输入

`/config` 或 `Ctrl+G` 打开设置页，包含模型、供应商、指令、技能、工具、沙盒、上下文、会话、MCP、界面和高级设置。供应商与模型按分组展示，`←→` 或 `Enter` 展开／收起；`↑↓` 选择，`Enter` 就地编辑单行字段，多行内容在弹出的小窗里编辑并用 `Ctrl+Enter` 应用。探索子代理模型与 `Ctrl+P` 共用同一个可搜索模型选择器，`Enter` 或 `Space` 打开，选中模型的同时确定思考等级（`Tab` 或 `←→` 就地切档，焦点不离开候选列表）；候选行右侧的规格卡只列真实生效的项——上下文窗口、输出上限、输入模态、价格、服务端压缩与思考等级，没有值的项连字段名都不出现；正文窄于 74 列或行数容不下整张卡时收起，改在行尾显示上下文数字。explore 的「沿用父会话当前模型」是候选列表最前面的伪条目。`Space` 切换开关，`Delete` 删除整组，`R` 恢复默认值，`F2` 切换全局／项目，`F4` 显示高级项，`/` 搜索。**每次修改都会立刻写入配置文件并让内核生效，不需要手动保存**；`Ctrl+Z` 撤回，`Ctrl+Y`（或 `Ctrl+Shift+Z`）重做，撤回记录只存在于当前进程内。密钥默认隐藏，`F6` 临时显示；写入前会校验配置及外部修改冲突。

设置页与主界面共用版式：左右各 3 格边距，滚动条是贴终端右缘的同一条 `▐`。选项卡与工具栏按钮放不下时换行，按钮一个都不丢；按钮写作「键位 动作」（`Ctrl+Z 撤回`、`e 展开全部`），`F4` 开着高级项时反白。字段树的标签列按整页最宽标签取 24–44 列，其余都给值列；超宽的值以 `…` 收尾，多行文本只露首行并注明 `（共 N 行）`，整数值的浮点显示为整数。底部说明区高度固定、内容贴底：描述原文最多两行（反引号片段按行内代码着色），下一行单独给出来源（`● 已在本文件自定义` / `○ 使用系统默认值`），提示条放不下时从左丢项、`Esc 返回` 恒保留。最底一行是反馈：失败红字 `✗`，其余中性色，都不铺底。

运行中 `Enter` 的默认行为是补充要求：消息先进入输入框上方的待发送区（前缀「插队」），等当前模型响应和工具批次结束、下一次请求开始前由 core 写入会话；写入后消息才移入转写。点击条目可撤回并还原到输入框，点击 `×` 丢弃；已经写入会话的消息不能撤回。`Ctrl+Enter` 把消息排到同一待发送区（前缀「队列」），点击可重新编辑，点击 `×` 取消；这两类消息都会等到真正发出/写入后才移出待发送区。可在"界面"页把运行中 Enter 改为"先停下再重新提问"：此时按 `Enter` 会立即停止当前回答（与 `Esc` 相同）并把消息排到队首，取消收尾后发送；这是显式选择，默认不启用。队列按会话隔离，在当前回答结束后依次发送；设置页或弹窗打开时暂停派发，关闭后自动继续。模型切换（含确认后的上下文压缩）与 `/compact` 在飞时同样暂停派发，等它们收尾再发送，不会把消息撞成 `SessionBusy` 报错。底部 statusline 显示 `Working`、`Thinking`、`Responding`、`Running`、`Waiting` 或 `Stopping`，输入框边框显示 `Esc Stop`。

输入框为空且当前没有运行中的提示时连续按两次 `Esc`，会打开消息回退选择器。`↑↓` 在当前用户消息的请求、模型回复和工具结果之间移动，`←→` 切换用户消息，`Enter` 在当前会话内原地截断到选中位置——不开新会话、不改会话 ID；选中用户消息时会把原消息恢复到输入框，供修改后重新发送。被截掉的尾部仍会列在时间线下方（标注「已回退」），选中其中任意条目按 `Enter` 即向前滚到该条目（含）；回退后一旦写入新历史，可前滚的尾部即作废。选中含提问调用的条目时按 `R` 可重新作答：该提问连同其答案及之后的历史被截掉，同一张提问卡片按原参数重新弹出，作答后模型带着新答案继续——答错或误取消的问题都能这样重答，重新作答不走回退栈，旧尾部随新答案落库一并作废。尾部里 spawn 的子代理会被孤立：仍在运行的立即停杀并从代理名册与通信面移除（transcript 文件保留在父会话 sidecar 中可查阅）；前滚接回其 spawn 引用后恢复可见，但已停的代理不会复活。前滚只保留在当前进程内存中，进程重启或会话卸载后即失效，孤儿标记则随会话持久保留。`/resume` 默认只列当前目录的会话，`Tab` 切换到全部目录；只有全部目录视图才在行尾显示会话的工作目录。

"界面"页可配置快捷键、思考与工具的默认显示档位、完成／需要你回答时的通知，以及 `↑`／`↓` 输入历史的范围（全局共享／只看当前项目，默认全局）。通知只在终端失焦时发送，通过 OSC 9 交给终端呈现；操作系统通知支持取决于终端。鼠标交互自动启用，没有捕获开关。提交过的内容（普通提示、除 `/btw` 外的 `/` 命令、`!` Bash）都会写入 `~/.moc/tui-history.jsonl`，全局一份、每行一条并带提交时的 cwd，重启后仍能召回；连续重复只记一条，召回列表最多最近 200 条。文件只给当前用户读写。

上游回显的模型 id 或推理强度与本地请求不一致时（网关降级、别名映射、静默降低强度等），转写区右上角会弹出一条告警胶囊，形如 `model a → b ｜ effort max → high`：复用右下角一次性提示的样式，但改用橙色强调，8 秒后自动消失，同一次提示内再次不一致只替换不堆叠，新提示开始时清除。只有上游确实回显了对应字段才会告警，网关不作声不产生任何提示。右下角的一次性提示按性质配色：操作反馈与引导用中性的工具强调色，失败（会话启动、送达、撤回、配置保存等出错）用错误红色；绿色不再用于提示，只表示成功状态。

`Ctrl+Enter`、`Ctrl+M` 这类组合键需要终端支持区分；不支持时 `Ctrl+M` 等同于 `Enter`，切换会话引擎请用 `Alt+M`（键位可在设置页重绑）。

引擎菜单与 `/engine` 提供三种会话引擎：`standard`、`ptc` 和 `(clm)` 实验引擎。引擎决定模型与工具的交互形态，只在会话还没有任何提示时可切换——发出第一条提示后引擎即锁定（撤回会话回到空白状态可重新解锁）。`/clm-experimental` 可直接启用 CLM；也可用 `--engine clm` 创建新会话。CLM 引擎下原始会话日志仍完整保留，模型维护的是独立实时上下文视图。`clm`、`ptc` 两个引擎有特性开关：`[features]` 配置段对应键置 `false` 后，该引擎从菜单消失，`session/new` 与 `/engine` 也会被 core 拒绝。

`/plan` 是与引擎正交的计划模式：可在任意引擎上进退，图例显示为 `引擎+plan`。进入、退出和批准计划都不改变模型，计划期间手动切换的模型也不会在退出时恢复。`/ask <问题>` 是单次提示级只读模式：该轮工具调用被限制为只读，提示结束后自动恢复，可在任意引擎上使用。`/autonomy` 切换自主程度：`default` 照常询问、`dont_ask` 自动代答 ask 工具（计划审阅仍照常弹出）、`unattended` 再进一步自动批准计划（压缩并执行）；自主程度默认为 `default` 且不显示，切到非默认值后图例追加 `+dont_ask`/`+unattended`。

计划流程先由模型调用 `plan` 保存到 `local://{plan_id}.md`（markdown 全量写，起草期原地复用同一 `plan_id`；edits 按 read 展示的锚点增量修订，无草稿时以最近一版已评审计划为底播种新草稿），再调用 `exit_plan` 结束本轮并打开审阅。审阅支持当前会话执行、压缩当前会话后执行、在新会话执行和继续计划；压缩和执行均沿用审批时的当前会话模型，新会话执行也继承该模型。选择"继续计划"或按 `Esc` 只关闭窗口，保持待审计划和计划模式，不自动对话；随后可用 `/confirm-plan` 重新加载同一份待审计划。新会话执行会先切换到已载入的子会话，再发送执行提示。

审阅窗口里按 `A` 切到带行号的源码视图批注：`↑↓` 移动，`v` 开始选行（再按取消），`c` 或 `Enter` 写批注，`Ctrl+G` 在正文里插入 ```` ```suggestion ```` 围栏并预填所选源码行，`x` 删除光标处的草稿，`Ctrl+S` 保存、`Esc` 取消；`s` 把草稿提交给 `session/plan_revise` 并自动发送 core 生成的修订提示。有上一版时默认展示「本版改动」（`session/plan_diff`），`D` 在改动与完整计划之间切换。批注视图支持鼠标：拖动即选行，滚轮移动光标。模型修订后以新的 `plan_id` 提交新版本，旧版转为「已被取代」并保留批注。

## 旁路问答 `/btw`

主任务运行时可在同一个输入框发送 `/btw 问题`，打开独立的 **BTW dock**。它不是模态：宽屏放在转写右侧，窄屏在转写下方，主输入和主任务始终可用。后续 `/btw 新问题` 沿用当前会话的旁路线程；单独 `/btw` 只重开面板，不发送模型请求。`Enter`、`Ctrl+Enter` 和文本粘贴 chip 都遵守同一分流规则，拒绝重复请求时原草稿不丢失。只接受文本，不接受图片。

- **隔离**：每轮使用当时主会话的模型与上下文快照，由 core 读取；不能调用工具，不把旁路问答写入主 context、transcript、持久输入历史或主 `/usage`。只读打开的会话也能提问（不申请写租约）。本面板单独显示模型、token 用量和实际回放轮数。
- **内存线程**：每个会话最多保留最近 20 轮。只有成功完整问答会回放给下一轮；取消、失败、输出截断的内容仍能浏览，但不会作为历史发送。退出应用即丢失。
- **单 flight**：整个 TUI 同时只运行一条旁路请求；再次提交会被拒绝且保留草稿。收起面板不会取消；清空、切会话会定向取消旁路，等待远端收尾后才允许新请求。
- **生命周期**：切到别的会话保留原线程，返回后用 `/btw` 重开；`/close` 成功卸载才清理对应内存，操作失败不清理。`x` 清空后，迟到响应不会把旧内容补回来。

| 操作 | 按键 / 鼠标 |
| --- | --- |
| 展开并聚焦旁路；已聚焦时收起 | `Alt+B`，或点击收起状态条 |
| 主输入与旁路切焦点 | 无补全时 `Tab`，或点击相应区域 |
| 收起但继续生成 | 旁路焦点下 `Esc` |
| 只取消旁路，不取消主任务、不退出 | 旁路焦点下 `Ctrl+C`（重复按也不退出） |
| 复制最新回答 | 旁路焦点下 `c` |
| 清空当前线程并取消其在飞请求 | 旁路焦点下 `x` |
| 浏览旁路记录 | `↑↓` / `j k`、`PgUp` / `PgDn`、`Home` / `End`、面板内滚轮 |

权限、提问、计划审阅等主 Modal 始终优先接收按键和鼠标；只有 Modal 关闭后，旁路快捷键才生效。要追问，先 `Tab` 回主输入，再输入 `/btw 新问题`。

## 显示档位

思考块与工具块各自有三档显示，`Ctrl+T` 管思考、`Ctrl+O` 管工具，循环切换（隐藏 → 简略 → 完整），右下角会提示当前档位；默认都是**简略**，"界面"页可改启动档位，`--detail hidden|brief|full` 可临时覆盖两层（不影响行式／`--print` 输出）。

| 档位 | 思考块 | 工具块 |
| --- | --- | --- |
| 隐藏 | 只留 `◆ Thought · X.Xs · Y tok/s` 一行 | 标题行；`grep`／`find` 附一行数量，`read` 仅标题行 |
| 简略 | 正文末尾 4 行（跳过段间空行，更早的折算成 `⋯ 还有 N 行`） | `bash`：命令（见下）+ 末尾 4 行输出；`edit` 等：正文最多 6 行（diff 同样 6 行），超出补一行 `⋯ 还有 N 行`；`grep`／`find`：只报数量；`read`：仅标题行 |
| 完整 | 正文全文 | 正文全文，不截断（`read`、`grep`、`find` 此时展开） |

补充规则：

- `bash` 命令在卡片里只出现一次：有 `description` 时标题给描述、命令落到正文的 `$` 行；没有描述时命令直接进标题（单行、超宽以 `…` 截断），正文只放输出；只有完整档且命令放不下（多行或超宽）时标题留空，正文用 `$` 行完整折行展示。简略档输出取末尾 4 行（更早的折算成 `⋯ 还有 N 行`）；隐藏档只留标题与耗时尾注；完整档命令与结果都按 core 交付的全文显示。
- `grep`／`find` 在隐藏、简略档不显示结果正文，只显示一行英文计数：`12 matches · 3 files`、`3 files`（工具耗时尾注照旧保留）。完整档才展开结果；失败时正文是错误原因，仍可展开查看。
- `read` 在隐藏、简略档严格只占一行（摘要带行号范围，如 `read crates/moc-tui/src/app.rs:585-670`），完整档才显示 `[path]`、带行号正文与分页 footer；失败时正文是错误原因，仍可展开查看。
- `run_code` 的标题同样取 `description`，不再回显脚本参数；脚本返回值仍按正文预览显示，子调用仍按父调用缩进单独成块。
- 完整档的「全文」以 core 已交付的输出为界：超出 40 KiB 预算的 bash 结果在正文里保留 `[… N bytes omitted; full output: …]`，TUI 另有 4001 行安全上限，超出补 `⋯ 还有 N 行`。`edit` 的结构化 diff 由编辑范围直接构造，不会因文件行数多而省略；`write` 的超大重写若超出 diff 对齐上限，正文末尾只出现一次 `⋯ 其余改动超出 diff 上限，未显示`，标题计数带 `…` 表示是部分值。
- 思考块的耗时与速率（`tok/s`）是本进程实测值，按每段思考流单独计时（工具调用或正文开始即定稿）；历史恢复的块没有这两项，标题行只留 `◆ Thought`，不会显示成 `0ms`。
- 同一批次（同一模型响应中的同名工具）合并成树形块：`• 名称 (N)` 落在块标记列，成员树挂在正文列；档位取组首块，每个成员的正文按该工具的策略逐行追加（`grep`／`find` 的计数行同样逐成员给出）。成员行右端是状态列（失败 `✘` + `⏱ 耗时`），摘要按剩余宽度截断、不挤掉状态列；末行统计只把成功落定的成员计入完成，如 `1/2 done · 1 failed`，运行中的另记 `N running`。
- 懒渲染保证只有视口内的块真正构造行：完整档不会因为历史很长而变慢。
- 点击块标题在该块的「完整 ↔ 当前收起形态」之间切换：收起形态跟随当前全局档位（简略档下是简略形态，隐藏档下是隐藏形态；`grep`／`find` 收起为计数行，`read` 收起为标题行）。
- `Ctrl+T`／`Ctrl+O` 切换全局档位时会收回该层所有手动展开，块重新跟随档位（另一层不受影响）。

### 后台任务

前台 `bash` 命令运行 60 秒后自动转后台（与 omp、dsh 类似），或通过 `Ctrl+B` 手动转后台（与 opencode 相同）。转后台时工具结果附输出尾部和优化建议，卡片标题显示 `· 后台 job_X` 徽标。每个会话最多同时运行 8 个任务（可通过 `tools.bash.max_running` 配置），满额时前台命令保持在前台并在结果中说明原因。

任务在后台完成时，会话空闲则自动唤醒新一轮提示（与 omp、dsh 相同，用户取消后不唤醒）；会话繁忙则静默完成，模型下次请求时可看到结果。后台任务 120 秒无输出时触发**无输出检测**（可通过 `tools.bash.stall_after_secs` 配置），core 会在下次提示时去重提醒模型——同一个命令模式只提醒一次。

运行中的前台 bash 卡片会在简略和完整档位显示实时输出（最后几行），命令执行 3 秒后卡片底部提示 `Ctrl+B 转后台`。状态栏右侧显示 `⚙ N` 标记（N 是后台任务数）。

`/jobs` 命令打开后台任务弹窗：`↑↓` 选择任务，`x x` 连按两次确认杀任务（首次按 `x` 标记为待确认，再按一次执行），`Esc` 关闭弹窗。任务状态用图标表示：`⚙` 运行中、`⚡` 正在杀、`✓` 已完成、`✗` 被杀、`⏱` 超时。鼠标点击任务行选中，点击已选中行执行杀任务。

后台任务按会话隔离：每个会话有独立的任务配额和状态。前台任务从 spawn 起就登记为隐藏任务，支持实时输出推送、手动转后台和杀任务；转后台后才在弹窗中可见。

斜杠命令包括 `/help` `/btw` `/new` `/resume` `/close` `/model` `/engine` `/autonomy` `/plan` `/confirm-plan` `/clm-experimental` `/ask` `/retry` `/agents` `/jobs` `/compact` `/usage` `/workflow` `/workflows` `/plugins` `/config` `/settings` `/context` `/features` `/goal` `/quit`；命令表、补全与帮助共用同一份注册表数据——依赖已禁用特性的命令（如 `[features] clm = false` 时的 `/clm-experimental`、workflow.enabled = false 时的 `/workflow`）不进补全，执行得到明确提示，`/help` 里仍列出并标注「特性已禁用」；`/plugins` 列出当前工作区已加载的插件、来源目录与它们注册的工具和命令，失败插件同时显示原因,插件注册的命令也出现在补全表里（与内置命令同名时内置优先）；`/plugins reload` 丢弃插件宿主并重新发现加载，插件因失败被停用后用它恢复，停用原因与 JS 调用栈同时留在转写里。`/confirm-plan` 仅在计划模式且有已写入的待审计划时打开审阅，其余情况只显示提示。`/retry` 接着现有上下文继续跑：不追加任何用户消息（不插入「继续」之类的替身），仅在该会话空闲且有上下文时可用——生成中、压缩中或只读会话只会给出提示。上一轮没跑完时（按 Esc 中断、上游断流、请求出错），core 先把那半截回合从会话里剪掉再继续：被打断的回复连同它的记账条目一起丢弃，界面上那段预览也跟着消失，看起来像什么都没发生；如果被打断的是一批工具调用且它们一个都还没跑，占位结果被删掉、调用本身留着，直接从原处重放，连模型请求都省一次；如果这批工具已经执行过一部分，则整段原样保留，让模型看到真实结果后自己决定下一步。上一轮正常结束时上下文保持原样。`/jobs` 打开后台任务弹窗，可查看、管理和杀任务（详见"后台任务"一节）。`/close` 卸载当前会话并释放跨进程写租约：另一个 `moc` 或 `moc web` 进程随后就能以写模式打开它；不关闭也不影响本进程继续使用。`/usage` 先给出会话统计（模型用时 = 生成 + 网络等待、工具调用用时、首 token 平均（TTFT）、输出速度），再以对齐表格列出当前会话各模型的调用次数、输入／输出 token、缓存命中率、思考 token、生成时间、TTFT 与 TPS，末行是全部模型的合计；统计来自会话 JSONL 里逐次模型调用的 `usage` 记录（工具耗时来自 transcript 里的工具结果记录），重启或恢复会话后仍然连续。`/context` 打开上下文正文窗（见下文），顶部信息条右端的进度条点击打开的是上下文占用窗，两者看的是同一份上下文。输入框以 `!` 开头的内容直接执行 Bash 并把命令及结果写入 agent 上下文，以 `!!` 开头则执行后只在界面显示，不写入 agent 上下文。`/model` 与模型选择器把目标模型和思考等级一起选中：切到别的模型时用该模型支持的最高等级，停在同一个模型时沿用配置或会话里写的等级；目标模型装不下当前上下文时先询问，确认后先切换再由新模型压缩上下文。`/features` 列出特性注册表：每条特性的生命周期阶段、当前生效开关、上下文 token 成本估计与生效的配置来源（`[features]` 覆盖键或原配置段路径）。`/goal` 是给会话立持久目标：目标存在且 armed 时每轮提示结束自动续跑下一轮（转写里是 `goal` 续跑卡片），直到模型确认达成或报阻塞、用户 `/goal pause` 或 `/goal clear`，或者取消/循环/出错摘掉 armed（`/goal resume` 重新武装并续跑）；`/goal edit <objective>` 改原文并作废在飞的旧轮。目标没有轮数上限也没有 token 预算。子代理会话不支持目标。

### 提问卡片

模型调用 `ask` 提问时弹出居中卡片：标题栏是问题 `header`（没有则「提问」），正文区先给问题全文（加粗、折行，多行问题完整显示），下面是选项列表与固定的「✎ 自定义」行；选项含义（description）缩进显示在选项下方，终端太矮时先省略它们，单选题用 ○/●、多选题用 ☑/☐，推荐项在标签后缀「（推荐）」且高亮默认落在推荐项上——直接回车选中的就是模型建议的答案。聚焦项带预览（mockup、代码等）时宽终端左右并排、窄终端落到选项下方，`PgUp`/`PgDn` 滚动预览。

按键：`1`-`9` 直达选项（单选选中即推进，多选切换勾选）；`space` 切换勾选；`enter` 选中并推进（自定义行上是进入编辑）；`z` 直达自定义行开始输入（编辑态 `enter` 提交推进、`esc` 退回选项行，此时粘贴进的是这一行而不是输入框）；`y` 复制聚焦项；`tab`/`Shift+Tab` 前后切问题，`←`/`→` 同样翻看——只动指针、不写选择也不提交，回看时误触不会把答案交出去，确认推进始终是 `tab`/`enter` 的事。鼠标点击选项即选择（单选直接提交整单、多选切换勾选），点自定义行进入编辑。`Esc` 分层退让：第一次停泊——卡片留在屏幕上但不压暗正文，键盘交给转写区（`↑↓`/`PgUp`/`PgDn`/`Home`/`End` 滚动，`←`/`→` 翻看问题），输入框图例固定显示「Tab 提问」指路；停泊态 `tab`/`enter` 返回作答、`z` 返回并直达自定义行、点击选项直接选择并提交，再按 `Esc` 才取消整单。`Shift+X` 跳过整单提问：按「未回答」提交空答案；`Ctrl+C` 在任何状态（聚焦/停泊/编辑）下直接取消整单，与权限弹窗同语义。取消与跳过对模型都是明确语义而非错误；core 侧不设超时，用户不作答时提问一直挂起、卡片保持显示。

多问时逐问作答（首行显示「问题 x/N」，转写区的工具摘要显示「共 N 问 · 首问」），`Shift+Tab` 可回改上一问；所有问题答完一次性提交。

### 子代理

人类面只有一个子代理命令 `/agents`（等同 `Ctrl+N`）：打开名册后 `Enter` 把主 TUI **整个聚焦到该子代理的会话**——转写、输入框、状态栏、`Ctrl+C` 取消都属于它，直接打字发送即可交流（运行中在下一次安全边界注入，空闲则唤醒新回合）；`Esc`（输入框为空）或双击 `←` 返回主会话，返回时主会话按磁盘真相重载并还原回来前的草稿。聚焦期间头部常驻 `▸ 子代理 <标题>` 提示，名册与侧栏仍挂靠在主会话上，`Ctrl+S` 停止选中的子代理（聚焦时停的就是眼前那个）。创建子代理由主模型决定（`spawn_agent`），界面不提供人机新建入口。

## 剪贴板

`Ctrl+V` 粘贴剪贴板里的图片，没有图片时粘贴文本；Linux 下图片需要 `wl-paste`（Wayland）或 `xclip`（X11），WSL 直接读 Windows 剪贴板，Windows Terminal 里按 `Ctrl+V` 即可，无需额外配置。`Ctrl+C`、右键或 `y` 把拖选内容复制到终端与系统剪贴板（OSC52）；鼠标捕获开启期间终端自身的选区不可用，按住 `Shift` 拖选可临时交还给终端。

## Todo HUD

todo 非空时，转写区上方的间隙行（无间隙行时为转写区首行）右端常驻一行胶囊：`▌ ◆ 任务 2/9 · ▶ 当前任务`。当前任务按「进行中 → 阻塞 → 待办 → 已完成」选取；标题放不下时横向循环滚动，不截断中文。上游配置告警胶囊固定贴转写区首行右端，两者绝不同行：胶囊在首行时自动下移一行避让。转写里的 todo 树标题为 `◆ Tasks`，阶段与条目挂在正文列，条目续行悬挂对齐条目文本。

- 鼠标移入展开卡片，移出收起；点击胶囊/卡片固定，再次点击取消固定。
- 按住卡片可拖到转写区内任意位置，拖动后自动固定；位置在本次会话内保留。
- 卡片内容与转写 todo 树同源（`☑ ▶ ☐ ⚠ ✗`），超出高度时截断并显示 `… 还有 N 行`；与内联图片重叠时暂时撤下图片。
- warning 胶囊出现时，折叠胶囊下移一行；终端高 ≤9 行、宽 <28 列或转写区过矮时 HUD 隐藏。

## Statusline

内置渲染是「左侧运行状态 + 右侧统计」两段：`Working · 3s … ⇅ 输入 › 输出 › tok/s › 费用`；右侧的输入／输出 token 与 tok/s 都是**整个会话的累计值**（与 `/usage` 读同一份 core 统计，在会话加载、每次提示结束与上下文压缩后刷新），不是单次调用的统计（提示进行中数字停在上一次刷新，收尾后跳到新累计）；其中 tok/s 只除生成阶段耗时，不含首 token 等待与工具执行。模型与模式在输入框下边框右端，工作目录/分支/上下文进度在顶部信息条（费用需要模型 pricing 配置）。

可在 `~/.moc/tui.toml` 用模板自定义（占位符按语义着色）：

```toml
statusline = "{model} * {status} -> {workdir}"
```

可用占位符：`{model}` `{status}` `{context}` `{context_percent}` `{workdir}` `{branch}` `{todo}` `{tokens_in}` `{tokens_out}` `{tok_s}` `{prompt_elapsed}` `{cost}`。`{tokens_in}`、`{tokens_out}`、`{tok_s}` 与会话累计口径一致；`{todo}` 仍可用在自定义模板里（内置渲染不再显示 todo）。

## 上下文占用窗

点击顶部信息条右端的上下文进度条打开。窗内按 `system`、`project`、`skills`、`tools`、`messages` 逐块列出估算 token 与占已用上下文的比例，每块的色标与下方色条上对应那段同色。色条按模型上下文窗口定标：已用部分落在左侧，右侧 `─` 是剩余窗口，空会话整条都是空窗口；色条下方标注各分块右界的累积用量，空间不够时只保留挤得下的标注，「已用总量」与右端窗口上限优先。token 按 1k / 1m / 1b 分档（`999 → 999`、`9030 → 9.03k`、`1_200_000 → 1.2m`），全 TUI 同一套写法。

## 上下文正文窗

`/context` 打开：窗内列出**真正送进模型的内容**，顺序与请求一致——系统提示片段（`intro`、`tool policy`、`ptc runtime`、`mcp servers`、`repo rules`、`skills`、`plugins`、`subagent`、`environment`、`append`）、逐个工具 schema（分块名就是工具名）、注入消息（`compaction summary`、`active plan`、`active todos`、`grok build summary`、`system reminder`）与会话消息（`user`、`assistant`、`tool result`、`bash`、`agent`）。每块一行标题，`▌` 色标与分块名同色（按分块顺序取调色板），右端是该块单独估算的 token；标题栏显示合计与窗口上限，与占用窗、顶部进度条同口径。新会话只有前面组装好的上下文，消息部分为空。

正文超过 6 行的块默认折叠成前 6 行加一行「… 还有 N 行 · 点击展开」，点标题或正文任意一行展开，再点收起。单块正文超过 256 KiB 时由 core 按字符边界截断，块尾标注被丢掉的字节数。窗口约占终端四分之三宽、五分之四高（上限 120×40），右缘是可拖拽的滚动条（按在滑块上保持抓取点，按在轨道空白处把滑块挪过来），鼠标滚轮一次三行。

键盘：`↑↓`/`k`/`j` 逐行滚动，`PgUp`/`PgDn` 翻页，`Home`/`End`（`g`/`G`）跳到顶／底，`Tab`/`Shift+Tab` 切换分块（自动滚进视口，高亮该块标题），`Enter`/`空格` 展开收起当前分块，`e`/`c` 全部展开／收起，`Esc`（或 `q`）关闭。

窗里是会话状态里存着的内容；尾部提醒（当前模式、本地时间、后台任务、工作区变更、违规告警）每次请求现生成、不落进会话，因此不在窗内展示。

## 工具调用 Diff

edit / write 执行时由 core 生成结构化 diff（上下文 3 行、近邻 hunk 合并），经 `ToolFinished` 携带到前端。`edit`（含 `move` 的目标文件）按已验证的编辑范围直接构造 hunk，不跑全文件 LCS，因此文件再大也不会把少量改动误判成截断；`write` 先剥离与旧文件的共同前后缀，只对差异窗口做 LCS，差异区域超过 2000 行才置截断标记。越出工作区的写入在授权弹窗里再给一次预览：`edit` 是待应用 diff（无法完整预览时不带），`write` 另附最多 40 行 / 4 KiB 的内容摘录，超出以 `[...]` 截断，确认后才落盘。

`edit` 接受单文件 `{path, edits}` 载荷，`edits` 只作用于一个源文件；`move` 可把源文件的行块搬到 `target_path`，因此一次调用可能同时写入两个文件（两侧都仍需先 `read`）。锚点在 read/diff 展示时分配，行位移后保持不变；同一行被重新展示时以最新锚点为准。批量多文件 `files` 载荷会以 `E_BAD_PAYLOAD` 拒绝。

## workflow

`/workflow [指令]` 激活本会话的 workflow 功能（`session/workflow_activate`，成功后有指令就作为提示发送，失败显示错误）；`/workflows` 打开 run 列表弹窗。有活跃 run 或待审批时，prompt 图例行显示 `⚙N跑·M审` 胶囊——点击优先重开最小化的审批窗，否则打开 run 列表。

**审批窗**：↑↓/`j``k` 选 role 或 ModelRef 行，`Enter` 打开模型选择器（含思考等级，复用现有选择器），`a` 批准（decision 携带 `role_models`+`model_ref_map` 覆盖）、`r` 拒绝（进反馈输入行）、`Esc` 最小化；role/ref 行单击选中、选中后再单击开选择器，底部键位提示可点击。编排图按最长路径分层，宽度不足退化为纵向列表。

**run 面板**：`Enter` 改 role 模型（`session/workflow_set_role_model`）、`s` 停止、`r` 续跑；artifacts 按类型渲染（chart 文本图、table key 去重、metrics 最新值、board 按 status 分列、file/markdown 全文），`v` 切换 artifact 版本、`o` 查看 file/markdown 全文、`Esc`/`q` 返回。
