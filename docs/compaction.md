# moc 上下文压缩

前几节描述默认 `compaction.method = "moc"` 的摘要阶段：先尝试本地 shake，空间不足再进入 soft。末节介绍新增的 `eocc` 实验算法；现有 `moc`、`grok_build` 均保留，默认选择和会话文件格式不变。

## 信息优先级

- 新的真实用户要求优先于旧摘要和助手推断。同一 ask 问题只保留最新有效答案。
- 决策候选带有 `user`、`assistant decision`、`previous checkpoint` 来源。用户原话优先；普通状态汇报、代码块、引用和资料工具输出不会自动升级为项目决定。
- 旧摘要只回收 Decisions 节的显式决定。它们作为可修订证据进入提示，不再要求逐字永久继承。摘要模型负责语义核对，不用关键词猜测任意自然语言之间的矛盾。
- 较早的 ask 答案仍传给摘要模型，但在后面出现新的真实用户消息时，不再将其强制锁为唯一合法答案。
- 摘要契约明确区分“最后一次通过验证的状态”和“之后尚未验证的改动”，不再要求复述所有历史数值、错误、代码与文件。

## 关键事实校验

用户、助手正文中的路径、标识符和数值仍参与校验。工具参数先按 JSON 解析，只提取已知文件工具的路径；`write` 正文、`edit` 替换正文、补丁行号、JSON 转义、未知工具的大段代码不再直接变成必保留锚点。导入的旧编辑协议只提取 `[path#hash]` 的文件头。

上一份摘要仅补充 Current Work / Next Step 的定位符，不再硬锁旧数值或已被新指令覆盖的否决方案。挑选候选摘要时，先比较用户要求缺口，再比较锚点覆盖，不用更高的零散命中数补偿更多用户要求缺失。

## 保留尾部与用户原文

`keep_recent_tokens` 按完整消息／工具调用组选择连续后缀，不再向前扩张到整个用户回合。

- 工具调用和所有结果作为同一组；并行结果、组内运行时提醒及尚未返回的工具调用不会被拆散。
- 最新不可拆分组单独超过预算时，保留整组是明确例外；不是把整条用户回合都保留。
- `keep_recent_tokens = 0` 为纯摘要，但尚待执行的工具调用仍保留，防止后续结果失去所有者。
- 最新真实用户消息若已移出尾部，会从原始日志单独回放。短请求完整保留内容块；长粘贴采用不超过4,096个本地估算token的首尾摘录，明确标记省略内容及历史入口。
- 已在尾部内的用户请求不重复注入；会话重载和再次压缩仍可恢复，ResetBoundary 之前的旧要求不会复活。

因此总体上下文仍需加上系统、工具、摘要和用户摘录。不能把 `keep_recent_tokens` 解释成整个压缩后上下文的硬上限。

## 输入预算与观察

超长历史摘录按同一套 Unicode token 估算截取，包装和消息开销也计入。每次修复根据实际提示长度重新拟合历史；前缀本身无法放入预算时明确报错，不发送已知超窗请求。

开启 `RUST_LOG=moc_core::compact::soft=debug` 可查看：

- 每次请求的输入估算与省略轮数；
- 每个候选的结构／覆盖校验结果、命中数和用户要求缺口；
- 总尝试数、最终采用哪次摘要、是否使用确定性兜底；
- 保留尾部与单独用户摘录的 token 数。

这些是本地估算和算法诊断，不代替供应商的实际 usage。

## 验证与实验边界

本轮回归覆盖了资料中的 `Rejected proposal`、编辑控制词／行号、旧问答覆盖新答案、长用户回合、并行工具结果、待执行调用、用户原文重放、重置隔离及中文摘录预算；本地固定响应测试验证正常压缩请求、连续重压缩、会话重载、上下文预览和溢出恢复。

没有重新运行400k／600k真实模型实验，也没有将旧录制响应冒充新算法的真实生成结果。新提示与消息边界已经改变，旧实验仍应使用其冻结二进制严格重放；验证遗忘率、摘要质量及重试成本是否提升，需要另行运行同语料真实模型对照。

## EoCC：实验性交接状态

依据 NVIDIA [《You don’t need long context》](https://arxiv.org/abs/2611.05306)，重点采用 §2.4.1 的 EoCC、§3.1 的按需历史回查、附录 A 的未来工作相关性和附录 G 的交接结构。这是适配 MOC 的算法，不是论文 harness 的逐行复刻，也不是论文提出的经过专门训练的 SSSM 模型。

### 与既有实现的区别

- `moc`：本地修剪优先；必要时生成 checkpoint，保留最近历史并校验关键事实。
- `grok_build`：保留现有九段摘要、两遍预火和最后用户查询回放。
- `eocc`：直接在当前会话前缀后追加交接请求；普通历史由任务原文和六段状态替代。状态只服务剩余工作，不按轨迹中的出现频率分配篇幅，不以旧路径／数字的覆盖率决定是否接受。

六段分别为 Objective、Established Facts、Applied Changes、Verification、Dead Ends、Remaining Plan：当前目标与完成条件、未来需要的证据、已修改内容及验证状态、检查与障碍、不能重复的失败方案、按执行顺序排列的剩余工作及立即下一步。旧摘要是可修订状态；用户纠正优先，资料和工具输出不会变成用户指令。

### 确定性保留与预算

- 任务原文从原始 transcript 重建，不让摘要模型反复转述。优先保留重置之后的首条请求及最新请求，按时间顺序回放；长请求采用首尾摘录，引用单条至多 3,072、本块至多 8,192 个本地估算 tokens。省略的中间请求有计数和原文入口，活跃约束仍要求交接模型记录。
- 子代理收到的父代理指令纳入任务；子代理报告、工具输出、本地注入以及重复 goal 续跑提示不冒充真实用户请求。goal 目标由现有运行时提醒恢复。
- 生成简报正文至多 4,096 个估算 tokens，并进一步受实际剩余恢复预算约束。提交前计入系统、工具定义、任务引用、简报包装、归档指引、运行状态提醒和未完成工具组；空间不足时报错，不截掉任务或提交半份状态。
- 摘要请求输出上限为模型配置上限与 8,192 的较小者，输入扣除这部分输出空间及系统、工具和交接提示。输入太长时保住先前 checkpoint 与任务，再拟合最近完整轮次，并明确告知存在省略。没有足够空间时不发送已知超窗请求。
- 检查简报段落、正文与长度；最多三次生成，拒收原因交给下一次修复。非正常结束（包括长度截断、工具调用）、上游失败或修复耗尽不替换活动历史，不制造确定性假摘要。完整 transcript 仍保存，归档复用现有机制。
- 不使用 `keep_recent_tokens`、`protect_recent_tool_tokens`、shake 参数或 Grok 预火。唯一保留尾部的例外是尚未收齐结果的工具组；否则后续结果可能失去原调用。

### 如何选择

设置页的压缩算法列表增加 `EoCC（实验性：交接状态）`，也可配置：

```toml
[compaction]
method = "eocc"
```

选择算法不会修改阈值。要试验论文的短工作上下文策略，可另外使用固定阈值，例如：

```toml
[compaction]
method = "eocc"
threshold = { mode = "tokens", value = 48000 }
```

48K 是可调的试验起点，不是该算法新设的默认值，也不是峰值上下文硬上限。MOC 的系统提示、工具定义和运行状态可能比论文的极简 harness 大得多；自动续写需要压缩后落入触发线的 80% 恢复区。先看上下文占用再设阈值，不应照搬 16K。很短的历史手动压缩后可能因为新增交接包装而变长。

### 论文结论与验证边界

- 论文支持在受测任务上用较短上下文配合状态维护，并不证明长上下文永远无益。附录 D 中 Qwen 3 Coder Next 在 SWE-bench Verified 的 16K/12K 配置由 53.0% 降至 3.6%；压缩能力和每轮可用工作空间有明显模型依赖。
- §5 的 SAC 是每次动作后更新状态；SSSM 是专门训练的语义状态模型概念。本实现仅增加 EoCC 选项，不改变执行引擎为 SAC。现有 CLM 自主管理上下文可作为研究接口，但不等于已经实现或训练了 SSSM。
- 附录 B 的大幅降本依赖估算的短上下文服务定价，不能直接套用当前 API 账单。频繁压缩还会增加摘要输出、减少缓存复用；评估必须同时看实际输入／缓存／输出用量、任务完成率和重新检索成本。
- 本地固定上游验证用于检查压缩、连续重压缩、落盘回放、任务引用预算、重置隔离与失败不改写历史。另用临时协议程序实际执行压缩及 `read history://compaction/INDEX.md`，确认归档入口可用；这些均不证明真实模型的简报质量、准确率或成本优于另外两种算法。
