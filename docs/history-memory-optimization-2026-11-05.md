# 长历史与巨型 Markdown 内存优化（2026-11-05）

## 范围与交付

本轮承接上一轮冷初始化/只读代码页优化，处理三类业务内存：未语义压缩的旧正文、重复历史元数据、巨型助手 Markdown 的排版行。保留完整正文、JSON 日志和前端协议格式；默认 release 配置不变。

### 历史正文：存储冷热与模型上下文分开

复用既有的私有匿名文件快照与只读映射，而不是直接映射可能被回退重写的源日志。恢复期间按批次冻结旧正文；最近窗口最多 128 条且正文预算 2 MiB，累计新正文约 4 MiB 或达到批次上限时触发。消息是否仍在模型上下文，不再决定它是否必须以解析后的对象驻留堆。

冻结不会执行模型摘要、修改 context_start 或删掉原文。文件映射会持有完整 JSON，临时读取按条解析；原日志替换不影响已发布快照，读取不需要依赖可失效的旧偏移。冻结写入失败继续保留原始内存正文和已提交日志。

请求前的工具配对使用归档 ID 索引，普通旧 assistant 消息不为此全量解码。三种模型编码器按条使用独立临时解析槽，避免编码一次后把整个共享历史永久加热；实际 HTTP 首发/重试共享 Bytes，请求体不再每次深拷贝。请求编码仍会构造线上 JSON，因此发送峰值仍随请求本身大小增长，不宣称已实现整条 HTTP 管线的恒定内存流式编码。

### 历史元数据：一份共享消息，两组顺序

内存日志改为 StoredEntry：消息记录保存 parent_id、finish_reason 与 Arc<TranscriptEntry>；展示序列保存同一 Arc。物理日志顺序和工具结果展示顺序继续独立，其他日志事件按需装箱，不再由最大消息变体撑大整张日志数组。

回退、前滚、重写、导出和子会话派生在边界恢复原 Entry。写时复制保证旧快照不随新状态改变，内容替换同时更新日志和展示两组句柄。

对外 JSON 与磁盘格式不变；Rust 内部 SessionState 的公开字段类型改变，仓库内调用者和性能示例已迁移到共享表示及 log_entries() 导出入口。

### Markdown：完整解析、分页排版结果、按视口解码

超过 256 KiB 的助手正文，按 128 行封口为独立 zstd 页，保留每个 span 的文本、颜色、样式与行对齐。绘制仅解码视口加上下各 128 行预读；图表入口的插入位置、图片槽位、复制行文本仍使用准确的全局行号。

压缩页使用 Box<[u8]>，释放 zstd 按最坏压缩大小预留的 Vec 容量。屏外压缩布局按 8 MiB 预算保留，超预算淘汰屏外块；重访时从完整正文重建。当前视口的布局不能为满足预算被截断，因此这是屏外缓存预算，不是整个进程或任意巨型单行的硬上限。

代码高亮改为逐行喂入同一高亮器，保持多行注释/字符串状态；段落与代码行折行直接输出至页容器，不再先收集整个块的高亮行和终端行 Vec。

**本轮没有按任意字节截断 Markdown，也没有改变其全局解析语义。** 引用式链接、嵌套结构和表格仍由原解析器处理。首次解析、宽度改变及流式追加后的有效布局更新仍需要处理正文；不是仅解析视口对应的原文。这个选择保留准确总高与跳转，不引入估高纠正造成的画面跳动，但首次解析仍有随文档增长的成本。

## 逐项测量与排除的方案

基线是上一轮已优化的 release（包括冷代码页回收），不是最初未优化程序。沿用隔离合成语料和真实 120×40 PTY：空会话、100 条、10 万条未压缩、10 万条定期压缩、单条约 8 MiB Markdown。每场景三次，报告中位数；输入后与静置后的 RSS 分开。

- 第一次 Core 候选已显著降低长历史内存，但每条恢复记录重复扫描近期窗口，导致 20 秒以上就绪。改为只在批次触发时计算冻结范围后，恢复耗时降回数秒。
- 第一版排版页虽然压缩内容很小，返回 Vec 却保留过大的预分配容量。通过分配器统计确认后改为精确长度装箱。
- 试验性 malloc_trim 对当时巨型回复只少约 0.5 MiB RSS，因此没有添加到产品。没有更换分配器或限制线程数。
- 文件映射和代码页回收减少进程 RSS，不代表系统页缓存立即释放相同数量的物理内存；私有历史快照会占临时磁盘空间，随快照引用释放。

## 性能对照

下面的基线已经包含上一轮冷代码页回收；本轮下降主要来自业务表示与排版缓存变化。结果采用包含远端图表屏幕坐标修复的最终 release（附件产物名 `moc-verified`）。

| 场景 | 静置 RSS 前 → 后 MiB | 匿名 RSS 前 → 后 MiB | VmHWM 前 → 后 MiB | 就绪耗时前 → 后 s |
|---|---:|---:|---:|---:|
| 空会话 | 7.42 → 7.88 | 3.86 → 3.72 | 24.78 → 28.52 | 2.31 → 2.31 |
| 100 条 | 11.64 → 12.08 | 8.14 → 7.91 | 32.71 → 36.16 | 2.34 → 2.33 |
| 10 万条未压缩 | **321.09 → 82.20** | **317.53 → 78.00** | **343.41 → 108.76** | 3.63 → 4.21 |
| 10 万条定期压缩 | **106.36 → 77.11** | **102.63 → 72.79** | **127.55 → 101.15** | 4.25 → 3.96 |
| 单条 8 MiB Markdown | **133.56 → 66.55** | **130.00 → 54.40** | **164.04 → 104.52** | 4.01 → 4.10 |

就绪耗时含约 2.3 秒隔离 PTY 的终端能力协商等待；不能全部归为应用计算。这里每次从持久日志重建私有快照，最终未压缩长历史恢复约多 0.58 秒，其他候选轮次曾多约 1.05 秒；这是减少正文堆驻留所付出的 CPU/I/O 成本，不隐去该回归。空、小会话的静置内存没有改善，启动时文件工作集增加约 3–4 MiB；匿名内存未增加，文件布局与预读会影响该部分。输入回显中位数约 18ms。

8 MiB Markdown 连续 20 次 PgUp、20 次 PgDown，再从 120×40 缩到 100×35，三次对照均找到最终正文标记：

- 从按键到首批终端输出的翻页中位数：0.50 → 0.53ms；p95 的三次中位数：0.69 → 0.63ms。这是首输出时延，不能当成完整屏幕重绘耗时，也不能把小幅波动当作提速。
- 缩放后尾部正文就绪中位数：2.06 → 1.94 秒。共享开发机后台负载及页缓存有噪声，不作为稳定倍速承诺。
- 缩放后的 RSS：基线约 153–160 MiB，最终版约 84–98 MiB。
- 基线启动采样首轮有 121 次 major fault，随后两轮为 0；最终版三轮均为 0，另一候选首轮曾有 164 次。翻页阶段未增加 major fault。不能声称冷磁盘恢复没有成本。

探针使用无控制终端的 PTY，窗口尺寸 ioctl 不会自动送 SIGWINCH。最初基线也未触发缩放，修正探针显式发送该信号后完成上述对照；没有删除尾部完整性断言。
