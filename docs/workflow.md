# 工作流（Workflow）

工作流功能适合单轮对话难以一口气完成的**多阶段复杂任务**：模型把规划、实现、评审等步骤写成一段 TypeScript 编排脚本，由引擎按确定性顺序执行——每个角色运行在干净的独立子代理上下文中，敏感命令执行前先经你审批，中途失败后还能跳过已完成步骤直接续跑。

## 按需激活，未启用零干扰

- 在对话中输入 `/workflow [你的任务]` 即可为**当前会话**激活工作流（带任务文本时会激活并直接发给模型）。
- **未激活的会话完全不受影响**：不会向模型暴露工作流工具或说明，不占用任何额外 token。
- 激活后，模型会自动看到内置的 `workflow-authoring` 编写规范（完整脚本 API 与错误码以该文档为准）。

> 工作流里声明的临时角色仅属于当前运行实例，执行结束或停止后自动终止，不会污染普通子代理角色目录，也无法被普通消息或跨工作流唤醒。

## 审批窗口

当模型提交新工作流、修订脚本或补充待填步骤并涉及外部命令（`world.run`）或审批检查时，终端与 Web 都会弹出一致的审批窗口：

- **编排图**：按阶段依赖分层展示，标出阶段名、角色、并行扇出（`×N`）、调用次数与待填缺口（`hole`）；实线表示数据依赖，虚线表示顺序依赖。
- **角色模型配置**：可为每个角色及脚本引用的模型别名单独挑选模型和思考等级（默认沿用会话模型或脚本声明）。
- **命令清单与脚本全文**：集中列出所有将要执行的外部命令及完整源码（补充缺口时仅列出新增命令）。
- **批准或拒绝**：确认无误后批准运行；拒绝时可填写修改意见直接回传给模型。

## 运行面板与产物查看

输入 `/workflows`（或点击界面状态徽标）可打开运行列表与实时面板：

- **实时状态图**：各阶段与角色按运行状态（等待 / 运行中 / 完成 / 失败 / 已取消）实时着色，并展示进行中与已完成的调用数及 token 消耗。
- **运行中切换模型**：可随时修改某个角色的模型，后续派发给该角色的新步骤立即生效。
- **停止与续跑**：支持随时停止工作流，或在故障修复后从中断点续跑。
- **结构化产物（Artifacts）**：支持查看 `file` / `markdown` 全文、`table`（按键去重）、`metrics`（最新指标）、`board`（按状态分列看板）与 `chart`（TUI 展示字符折线与数值表，Web 渲染为 Mermaid 图表）；同一产物多次写入会自动保留版本供切换查看。

## 日志重放、续跑、修订与缺口

- **确定性重放（Resume）**：每一步角色提问和外部命令的结果都记录在运行日志中。中断后续跑时，已完成的步骤直接从日志重放，**不消耗任何模型请求**；若输入与历史记录不一致则报错停止。
- **分叉修订（Amend）**：修改脚本重新提交时，未受影响的前序步骤会零成本从旧记录继承到新运行实例（不改写旧运行的审计日志），仅从首个发生变化的位置继续执行。
- **动态缺口（Hole）**：脚本可通过 `hole("名称")` 在某个节点暂停，交由主模型根据前面产出的真实信息补写后续代码；若补写内容含新外部命令，会再次弹出审批窗，通过后继续运行。
- **脚本保存与参数**：常用工作流脚本可保存在当前会话中复用，并支持运行前传入自定义 `args`。

## 命令执行安全（`world.run`）

工作流里的 `world.run(argv)` **不经过 Shell 解释器**，直接按固定参数数组执行：包含 `$(...)`、`;`、引号或空格的参数都按原样传递，不存在命令拼接注入风险。它同样遵守当前会话的沙盒模式与 CPU/内存资源上限，并在审批窗口中逐条公示。

## 配置与存储

可在配置文件 `[workflow]` 段调整默认限制：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 工作流总开关；设为 `false` 时禁止激活 |
| `max_concurrency_ceiling` | `16` | 同时在飞的角色提问数硬上限 |
| `world_run_timeout_ms` | `300000` | 单条 `world.run` 默认超时（毫秒） |
| `file_read_bytes` | `1048576` | 脚本内单次读文件大小上限（1 MiB） |
| `log_bytes` | `8192` | 单条日志大小上限 |
| `ask_max_repairs` | `3` | 角色结构化输出校验失败后的自动修复次数上限 |

所有运行数据保存在会话目录下：

```text
<session>/workflows/
├── saved/               # 已保存的脚本
└── runs/<run_id>/       # run.json 快照、journal.jsonl 日志、script.ts 与 artifacts/
```

> 开发者测试命令：`cargo test -p moc-core --test integration workflow_flow`（需要真实 `moc` 二进制，测试辅助会自动定位或构建）。
